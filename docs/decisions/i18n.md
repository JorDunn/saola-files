# Decision: message catalogue for user-visible strings

Date: 2026-11-19. Issue: #12.

## Problem

User-visible text was string literals scattered across `src/ui/` and
`src/app/`. Translating later would mean touching every file at once. We
want English only now, but every string behind a catalogue so later work adds
messages, not literals, and translators can start whenever they want.

## Requirements

- Pure Rust (no C library, no `gettext`).
- Plurals and named arguments ("1 item" / "3 items", "{name} already exists").
- Catalogue embedded in the binary; no runtime file lookup, no locale
  detection (both out of scope).
- A missing id must never panic.
- Small dependency footprint: this is a file manager, not a web framework.

## Candidates (surveyed 2026-11-19)

| Option | Format | Plurals | Verdict |
| --- | --- | --- | --- |
| `fluent-bundle` 0.16 + `unic-langid` 0.9 | Fluent (`.ftl`) | Yes, CLDR rules through `intl_pluralrules`; selectors in the message | Chosen |
| `fluent-templates` 0.15 | Fluent | Yes | Adds a loader layer, directory walking and fallback-chain machinery we do not need with a single embedded locale. It is a wrapper over `fluent-bundle`, so choosing it later costs little. |
| `i18n-embed` 0.16 | Fluent (and gettext) | Yes | Adds `rust-embed`, a language-requester and desktop-selector layer. Built for locale detection, which is out of scope. |
| `rust-i18n` 4.x | YAML/JSON/TOML key tables | No grammar; plurals are hand-rolled per key | Proc-macro codegen, and translators would not get Fluent's selectors, so plurals and gendered text become code. |
| `gettext-rs` | `.po` | Yes | Binds the C `libintl`. Not pure Rust. |

## Choice

`fluent-bundle` with `unic-langid`, behind a small `crate::i18n` module
(`tr!` macro, `lookup` function). Fluent is the format translators already
know, its selectors express plurals in the catalogue instead of the code, and
the low-level crate lets us own the three things we care about: an embedded
`en-US` resource, no isolation marks around arguments (so the English output
is byte-for-byte what the literals were), and a total lookup (missing id
returns the id).

We use `fluent_bundle::concurrent::FluentBundle` so the bundle can live in a
process-wide `OnceLock` and be read from any thread.

## Consequences

- Strings live in `i18n/en-US/files.ftl`, embedded with `include_str!`.
- Adding a locale later is a second resource plus locale selection in
  `i18n.rs`; call sites do not change.
- Filenames are never part of the catalogue. They are passed as arguments and
  converted with `to_string_lossy` at the call site, at view time.
- Log and stderr text (`eprintln!`) stays outside the catalogue.
- A test (see `src/i18n.rs`) fails when a user-visible literal
  appears in `src/ui/` or `src/app/`, and when an id used in code is missing
  from the catalogue.
